# NetworkTransport

`NetworkManager` уже отправляет пакеты через `Transport` и принимает их через `PacketReceivedSpan`.
Снаружи прежний `NetworkManager.SendPacketToPeer(...)` работает как раньше, с отложенной отправкой.
Для немедленного закрытия батча: `NetworkManager.Instance.Transport.SendPacketToPeer(..., sendImmediate: true)`.

Самостоятельное использование:

```csharp
var transport = new NetworkTransport();
AddChild(transport);
transport.Setup(isServer, sceneMultiplayer, flushTickRate: 60, compressThreshold: 512);
transport.PacketReceivedSpan += OnPacket;

// Разрешено из любого потока. После возврата data можно переиспользовать.
transport.SendPacketToPeer(peerId, data, MultiplayerPeer.TransferModeEnum.Reliable, channel: 1);

void OnPacket(int peer, ReadOnlySpan<byte> data)
{
    // Основной поток; span действителен только до выхода из обработчика.
}
```

Узел сам вызывает `Tick(delta)` из `_Process`. Если он не добавлен в дерево, вызывайте `Tick` вручную
на потоке `Setup`. Не вызывайте оба варианта одновременно. `SceneMultiplayer` должен быть настроен
обычным способом и опрашиваться на том же потоке. `Setup` заново создаёт сессию и отменяет старые
очереди; используйте его до обмена данными. `Shutdown` и `_ExitTree` отписывают события и освобождают
буферы; уже запущенные задачи завершают освобождение самостоятельно.

## Батчи и порядок

- MTU 1350 — бюджет данных, передаваемых в `SendBytes`, включая заголовок транспорта.
  Заголовки SceneMultiplayer/ENet/UDP/IP добавляются ниже этого уровня.
- Формат: magic `0x435A` (UInt16 LE), версия `2` (байт), флаг/режим доставки (байт),
  длина распакованного тела (Int32 LE), канал (Int32 LE), затем записи
  `[Int32 LE длина][байты]` до конца тела. Отдельного счётчика или лимита числа записей нет.
  Нулевые пакеты поддерживаются.
- Для каждой связки `(peer, mode, channel)` есть собственный текущий накопитель и FIFO-очередь
  готовых батчей. Поэтому `A → B → A` превращается в `A:[1,3]` и `B:[2]`, если оба маршрута
  ещё не заполнили MTU. При достижении MTU и при `sendImmediate` закрывается только накопитель
  соответствующего маршрута.
- Один сырой пакет больше 1338 байт получает собственный батч, который может превышать MTU.
  Дальнейшая фрагментация зависит от сетевого peer Godot. Максимальный сырой пакет — 1 МиБ.
- Частичный батч закрывается с частотой `flushTickRate`. `FlushRawPackets()` также закрывает его вручную.
- `sendImmediate` обходит таймер накопления; он не блокирует вызвавший поток и не обгоняет предыдущие
  батчи. Готовые результаты отправляются из `Tick` каждый кадр, даже между flush-тиками.
- Параллельные вызовы упорядочиваются при захвате короткой блокировки очереди. Несколько задач
  могут сжимать разные маршруты одновременно; внутри одного маршрута следующий батч ждёт предыдущий,
  а разные маршруты не блокируют друг друга. За один `Tick` выдаётся до 4096 исходящих и 4096
  входящих батчей.
- На входе маршрут восстанавливается из заголовка батча: `PeerPacket` от Godot сам по себе
  сообщает только peer и байты. Поэтому входящие `(peer, mode, channel)` также получают отдельные
  FIFO-очереди уже после чтения заголовка.

Это сохраняет порядок **вызовов отправки внутри каждого маршрута** и **получения PeerPacket
от каждого `(peer, mode, channel)`**, несмотря на параллельную обработку. Порядок между
разными маршрутами не задаётся. Сквозной порядок и доставку обеспечивает `Reliable` внутри одного канала.
`Unreliable` по своей природе может терять/переставлять батчи; `UnreliableOrdered` может их терять.
Между разными каналами/режимами сквозной порядок не гарантируется. Транспорт не добавляет ACK,
повторную доставку или ожидание потерянных датаграмм поверх выбранного режима Godot.

## Сжатие и память

При размере тела батча (сырые байты + префиксы длин) **>= compressThreshold** запускается Brotli
с quality=1. Это относится и к отдельному большому пакету. Если сжатие не уменьшило размер,
отправляется исходное тело. Входящие размеры и все записи проверяются до вызова первого обработчика.

Массивы арендуются из `ArrayPool<byte>`, задания ThreadPool переиспользуются. Нет `Task.Run`,
замыканий или массива на каждый исходящий сырой пакет. Постановка делает одну необходимую копию
данных в принадлежащий транспорту буфер. Очереди и пулы растут при прогреве/новом пике нагрузки;
кодек также использует нативную память.

`PacketReceivedSpan` не создаёт отдельного массива для каждой записи. Совместимый `PacketReceived`
с `byte[]` выделяет собственный массив **только при наличии подписчика**; его можно хранить после
обработчика. Сам сигнал Godot `PeerPacket` уже создаёт managed-массив на входящий батч.

По умолчанию допускается до 4096 заданий/маршрутов и 32 МиБ суммарного бюджета буферов (вход +
резерв выхода). Лимиты задаются последними аргументами `Setup`; `maxBatchesPerTick` задаёт,
сколько готовых батчей каждого направления можно выдать за один тик. Они ограничивают очередь,
а не число пакетов в батче.
`BufferedBytes` показывает занятый бюджет, `QueuedBatches` — ожидающие/выполняющиеся задания и текущий батч.
При перегрузке исходящий вызов бросает исключение до принятия нового пакета. Входящий батч отклоняется
через `TransportError`. Ошибки `SendBytes` доступны через `SendFailed`; без подписчиков ошибки логируются.
Автоматических повторов отправки нет. На `PeerDisconnected` адресованные этому peer очереди отменяются;
broadcast (`peer=0`) остаётся адресованным текущим получателям.

## Проверки

```powershell
dotnet run --project Tests/NetworkTransport/NetworkTransport.Tests.csproj -c Release
dotnet build Tests/NetworkTransport/GodotHarness/GodotHarness.csproj
& '<Godot mono console executable>' --headless --path Tests/NetworkTransport/GodotHarness --max-fps 120 --quit-after 2400
```

Первый набор проверяет MTU, пустые записи, порядок, 8 конкурентных отправителей, большой пакет,
сжатие, повреждённый ввод, лимиты и остановку во время работы задач. Второй запускает настоящие
SceneMultiplayer/ENet на localhost: 300 пакетов в каждую сторону, оба API событий, фрагментация,
автоматический Tick и отправка из рабочего потока.

API Godot: [SceneMultiplayer](https://docs.godotengine.org/en/stable/classes/class_scenemultiplayer.html),
[правила работы с потоками](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html).
